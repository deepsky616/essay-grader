# P5 전체 흐름 확인 기록

확인 날짜: 2026-08-16

설계 기준: `docs/specs/2026-08-15-architecture-design.md`의 7.7절, 9절부터
14절.

## 결론

확정 점수 기반 입력 조립, 성취수준 판정, 익명 피드백 생성, 안전한 대체 문장,
지역 실명 삽입, 성적표와 인쇄용 문서 내보내기, 경계값과 피드백 화면을 구현했다.
전체 서버 검사 875개와 프런트엔드 제품 빌드가 성공했다.

현재 작업 공간에는 실제 한 학급 답안과 출력물, 본인이 정책을 확인한 외부 모형
키, 같은 답안을 종이로 채점한 시간이 없다. 따라서 실제 학급 전체 소요 시간과
종이 채점 비교, 실제 외부 생성 문장 평가는 하지 않았다. 아래 자동 검사와 합성
자료 결과를 현장 성능 근거로 사용하지 않는다.

## 자동 검사와 브라우저 확인

| 항목 | 결과 |
|---|---|
| 전체 서버 검사 | 875개 성공, 기존 사용 중단 예정 경고 7개 |
| 프런트엔드 엄격 자료형 검사와 제품 빌드 | 성공, 51개 모듈 |
| 프런트엔드 배포 의존성 감사 | 취약점 0건 |
| 미확정 점수 | 피드백 생성 400 차단 |
| 현재 자료 정책 확인 없음 | 피드백 생성 403 차단 |
| 현재 키와 모형 연결 불일치 | 피드백 생성 400 차단 |
| 생성 중 원본 변경 | 점수, 루브릭, 정책, 키나 모형 변경을 다시 확인해 저장 전 차단 |
| 부분 실패 | 기존 피드백을 지우지 않고 오류 원문을 숨긴 502 응답 |
| 다시 생성 | 학생 전원 결과를 한 번에 바꾸며 실행과 학생별 중복 없음 |
| 오래된 피드백 | 목록에 표시하고 인쇄 문서는 409 차단 |
| 인쇄 문서 | 지역에서만 실명 삽입, 출력값 가림, 학생별 새 쪽, 외부 자료 없음 |
| 성적표 | 문항별 점수, 총점, 수준, 문항 평균과 평균 득점률 확인 |
| 수식 주입 문자열 | 수식으로 실행되지 않도록 문자값으로 바꿈 |
| 넓은 화면 | 합성 학생 두 명, 피드백 두 장, 대체 문장 경고와 내보내기 동작 표시 |
| 390화소 화면 | 가로 넘침 없음, 동작 단추가 한 열로 바뀌고 표만 지역 가로 스크롤 |
| 화면의 오래된 자료 | 확정 점수 변경 뒤 경고 표시, 인쇄 링크 제거, 해당 카드 표시 |

## 피드백 내용 확인

실제 외부 모형 문장이 아니라 고정 응답과 오류 응답으로 계약을 확인했다.

- 6학년이 읽을 짧고 쉬운 말과 다음 행동 중심 지침이 생성 요청에 들어간다.
- 문항 설명은 확정 점수와 정확히 하나로 대응하는 루브릭 조항을 입력으로 쓴다.
- 빠진 문항, 없는 문항, 중복 문항, 감싼 제이슨, 추가 필드, 너무 긴 문장은
  그대로 쓰지 않고 확정 루브릭 조항 기반 대체 문장으로 바뀐다.
- 외부 호출 실패 문구는 학생 문서나 API 오류에 드러나지 않는다.
- 만점 여부와 관계없이 총평과 다음에 해볼 것을 요구한다.
- 실제 문장 다양성, 학년 적합성, 만점 학생에게 줄 내용의 질은 실제 외부 모형과
  한 학급 자료가 준비된 뒤 교사가 따로 읽어 평가해야 한다.

## 식별정보 경로 확인

- 외부 생성 입력에는 학생 실명 대신 `anonymous_token`이 들어가는 검사가 통과했다.
- 피드백 감사 기록에는 `purpose=generate_feedback`와 익명 표식이 남는다.
- 공통 전송 관문 검사는 감사 기록에 요청 본문과 API 키를 저장하지 않음을 확인한다.
- 외부 응답에 명렬표 이름이 섞여 와도 지역 마스킹 뒤 저장한다.
- 피드백 목록과 인쇄 문서에는 지역 학생 이름이 들어간다.
- 인쇄 문서는 `no-store`, 제한된 내용 보안 정책, 자료형 추정 차단 머리글을 쓴다.

감사 기록 목적 전체 목록의 실제 현장 확인은 P1부터 P5까지 한 번의 외부 실행이
필요하다. 현재는 각 목적별 자동 검사로만 확인했다.

## 성적표와 인쇄 문서 확인

- 합성 학생 두 명의 문항 점수 합과 총점, 1수준과 3수준 값이 일치했다.
- 문항별 평균은 2점과 1.5점, 두 번째 문항 평균 득점률은 0.75로 확인했다.
- 빈 학급도 머리글이 있는 파일을 만들며 학생별 문항 배열이 다르면 생성을 거부한다.
- 인쇄 문서에는 실제 학생 이름과 점수와 수준, 대체 문장 경고가 들어간다.
- 스타일에는 두 번째 학생부터 새 쪽으로 나누는 출력 규칙이 있다.
- 시스템 글꼴을 쓰는 인쇄용 HTML이므로 실제 피디에프 저장과 인쇄기의 한글 출력은
  현장 컴퓨터에서 한 번 더 확인해야 한다.

## 전체 소요 시간과 종이 채점 비교

상태: 실제 한 학급 자료와 종이 채점 기준 시간이 없어 미실행.

| 단계 | 소요 시간 |
|---|---|
| 준비, 평가 만들기부터 답안지 인쇄 | 미실행 |
| 스캔과 배치 처리 | 미실행 |
| 검토와 확정 | 미실행 |
| 피드백 생성과 내보내기 | 미실행 |
| 합계 | 미실행 |
| 참고, 같은 분량 종이 채점 | 미실행 |

## 실제 자료가 준비됐을 때 남은 절차

1. 실제 학생 답안 스무 장부터 서른 장과 교사가 직접 매긴 대조 점수를 준비한다.
2. 본인이 외부 제공자 정책을 확인한 키와 현재 키에 연결된 모형을 설정한다.
3. P1부터 P5까지 중단 없이 실행하며 네 단계 시간을 각각 잰다.
4. 생성된 피드백을 학생별로 읽고 학년 말투, 기준 밖 판단, 다음 행동의 구체성,
   만점 학생 내용, 문장 반복을 기록한다.
5. 감사 기록의 모든 목적과 익명 표식, 실명 부재, 본문 부재를 확인한다.
6. 성적표의 모든 학생 문항 합과 통계를 손으로 다시 계산해 대조한다.
7. 인쇄용 문서를 피디에프로 저장해 학생별 새 쪽과 한글 출력을 확인한다.
8. 같은 답안을 종이로 채점한 시간과 비교하고, 더 느린 단계가 있으면 화면이나
   처리 흐름을 고친 뒤 같은 자료로 다시 잰다.

실제 전체 흐름을 끝내면 이 문서의 `미실행` 값만 관찰값으로 바꾸고 별도 검증
커밋을 남긴다.
