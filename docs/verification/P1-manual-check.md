검사 날짜: 2026-08-16

## 결론

P1의 코드, 자동 검사, 제품 빌드, 지역 브라우저 검사는 완료했다. 실제 여덟 문항 예시 PDF와 개인 Gemini API 키가 저장소나 작업 입력에 없어 외부 루브릭 컴파일은 실행하지 않았다. 아래 실제 결과 칸을 추정값으로 채우지 않았으며, 개인 키 저장소를 임의로 읽지도 않았다.

브라우저 검사는 격리된 임시 자료 폴더와 시험 루브릭을 사용했다. 정답 후보 `10,000`을 `20,000`으로 바꾸어 저장한 뒤 쉼표가 보존되는지 확인했고, 확정 뒤 입력 잠금과 확정 해제 뒤 입력 활성화를 확인했다.

## 자동 검사로 확인한 안전 경계

- 언어 모형 제공자 실행 손잡이는 정확한 구체 자료형 하나이며 단일 전송 관문을 소유한다.
- `rubric_compile` 요청은 전송 직전 식별 정보 검사를 거친다.
- 감사 줄은 시각, 제공자, 목적, 익명 표식, 논리 자료 크기, 식별 정보 검사 결과만 가진다.
- 감사 파일에 요청 본문, 이미지, API 키, 추가 메타자료가 들어가지 않는다.
- 현재 API 키와 그 키에 묶인 모형을 같은 잠금 구간에서 읽는다.
- 앱 업로드 폴더 밖 경로, 없어진 파일, 심볼릭 링크는 외부 호출 전에 막는다.
- 선생님 평가 정본은 모형 출력, 루브릭 수정, 확정 때 덮어쓸 수 없다.
- 스키마 형태 오류는 정상 초안을 바꾸지 않으며, 업무 규칙 오류가 있는 초안은 확정할 수 없다.
- 확정 뒤 평가 정본 수정, 루브릭 수정, 재컴파일이 막히고 명시적 해제 뒤 다시 허용된다.

## 자료가 준비됐을 때 남은 절차

1. HWPX 원문을 지역 앱 밖으로 보내지 않고 PDF로 내보낸다.
2. 설정 화면에 본인이 확인한 유료 등급 API 키를 직접 저장하고 안전 목록에서 모형을 고른다.
3. 학년 6, 과목 수학, 총점 20으로 평가를 만들고 채점 기준표 PDF를 올린다.
4. 루브릭을 컴파일한 뒤 위 여덟 문항 표와 경고를 원본에 직접 대조한다.
5. 수준 경계값을 입력하고 확정 뒤 모든 편집이 잠기는지 확인한다.
6. `audit.log`의 마지막 줄에 목적 `rubric_compile`과 허용된 여섯 메타 칸만 있는지 확인한다. 본문과 키는 기록하거나 이 문서에 붙이지 않는다.

이 절차가 끝나면 미실행 칸만 실제 관찰값으로 바꾸고 별도 검증 커밋을 남긴다.
