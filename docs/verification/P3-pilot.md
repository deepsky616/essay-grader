# P3 파일럿 기록

검사 날짜: 2026-08-16

설계 기준: `docs/specs/2026-08-15-architecture-design.md`의 2절, 5절, 7.4절부터 7.7절, 10절부터 13절, 14절.

## 결론

P3의 인식 계약, 규칙 채점, 서술 채점 계약, 경로 결정, 실행 API와 최소 화면 구현은 완료했다. 현재 작업 환경에는 실제 학생 답안 스캔과 교사가 직접 매긴 대조 점수, 본인이 확인한 유료 등급 API 키가 없으므로 실제 정확도와 자동 확정 임계값은 측정하지 않았다. 기본값 0.90은 제품 동작을 위한 임시값이며 정확도 근거가 아니다. 실제 파일럿이 끝날 때까지 전체 검토 모드를 켜 두어야 한다.

## 자료가 준비됐을 때 남은 절차

1. 실제 학생 답안 20장부터 30장을 식별정보 영역과 응답 영역이 지정된 양식으로 준비한다.
2. 본인이 제공자 정책을 확인한 유료 등급 키와 현재 키에 연결된 모델을 설정한다.
3. 전체 검토 모드로 채점을 실행하고 모든 문항의 제안 점수와 교사 점수를 대조한다.
4. 문항과 유형별 건수, 일치 건수, 정확도를 위 표에 기록한다.
5. 판독 불가, 후보에 없음, 호출 오류를 세고 원인을 원본 크롭과 대조한다.
6. 후보 부족이 원인이면 루브릭 별칭을 보강한 뒤 같은 자료로 다시 측정한다.
7. 감사 기록과 점수 이유에서 출력 계약 위반 건수를 센다. 감사 기록에는 본문이 없어야 한다.
8. 자동 확정 후보를 신뢰도 구간별로 나누고 교사 수정이 한 건도 없는 구간만 찾는다.
9. 한 건이라도 틀린 구간은 자동 확정에서 제외한다. 안전한 구간이 없으면 전체 검토를 계속 쓴다.
10. 실제 근거가 생긴 뒤에만 임계값과 자동 확정 대상 유형을 이 문서에 기록한다.

실제 파일럿이 끝나면 `미실행` 칸과 임시 임계값 설명만 관찰값으로 바꾸고 별도 검증 커밋을 남긴다.
