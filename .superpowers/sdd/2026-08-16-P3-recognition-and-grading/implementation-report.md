# P3 구현 보고서

## 결과

- 인식 결과와 상태의 엄격한 값 계약
- 숫자 단위와 천 단위 표기 정규화, 실제 편집 거리 후보 맞추기
- 제한된 루브릭 조건식과 닫힌 문항 결정론 채점
- 답안 안 명렬표 이름 가리기
- 서술 채점의 점수, 기준, 근거, 판단, 신뢰도 출력 계약
- 작도, 서술, 닫힌 문항과 복합 문항 채점 길
- 신뢰도, 정합 품질, 학생 배정과 전체 검토를 합친 최종 경로
- 후보 분류와 전사 제공자, 익명 표식 감사 기록
- 채점 실행과 문항 점수 데이터베이스 모델
- 학생별 인식과 채점 파이프라인
- 정책 동의와 현재 키 결합 모델 게이트, 안전한 크롭 읽기, 원자적 결과 저장
- 설정 준비 상태와 결과 분포를 보여 주는 반응형 실행 화면

## 설계 반영

- 7.4절의 닫힌 후보 분류에는 후보에 없음과 판독 불가를 남겼다.
- 7.5절의 서술 판정은 루브릭 원문 밖 점수와 기준을 받지 않는다.
- 7.6절의 자동 확정은 채점 길 하나만 보지 않고 인식, 정합, 배정 품질을 모두 본다.
- 7.7절의 식별정보 경계에 따라 이름을 가리고 배치별 익명 표식을 모든 학생 외부 호출에 전달한다.
- 10절부터 12절의 소유 관계와 실패 경계에 따라 중복 문항 점수와 부분 저장을 막는다.
- 13절의 파일럿 수치가 없으므로 임계값 0.90을 근거 있는 값으로 표시하지 않고 전체 검토를 기본으로 뒀다.

## 검사

- 전체 백엔드 시험 748개 성공
- 파이썬 바이트코드 검사 성공
- 프런트엔드 엄격 자료형 검사와 제품 빌드 성공
- 프런트엔드 의존성 취약점 0건
- 넓은 화면과 390화소 화면에서 채점 경로, 정책 안내, 실행 잠금과 가로 넘침 확인
- 기존 사용 중단 예정 경고 7개, 새 경고 없음

## 남은 위험

- 실제 손글씨와 실제 제공자에서의 인식 및 제안 점수 정확도는 파일럿 자료가 필요하다.
- 실제 파일럿이 끝날 때까지 자동 확정은 근거가 없으므로 전체 검토 모드를 유지해야 한다.
