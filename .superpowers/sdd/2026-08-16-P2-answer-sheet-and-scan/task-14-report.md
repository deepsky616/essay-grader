# 작업 14 보고서

상태: 완료. 작업 수 한도로 주 에이전트가 구현과 읽기 전용 검토를 함께 수행했다.

## 구현

- 요청 범위와 독립된 뒤 작업 세션 팩토리
- 최대 100메가바이트의 600 권한 스캔 PDF 임시 저장과 실제 PDF 검사
- 평가, 학급, 응시 학생, 템플릿과 영역 준비 상태 선행 검사
- 답안지 쪽 수 곱하기 응시 학생 수와 스캔 총 쪽 수 일치 검사
- PDF의 200 dpi 회색 렌더와 쪽별 및 전체 화소 제한
- 템플릿 페이지와 응답 및 식별정보 영역 조립
- 파이프라인 결과 학생 수, 순서, 이미지, 품질과 상태 선행 검사
- 700 임시 배치 폴더와 600 PNG 저장
- 최종 폴더 이동과 데이터베이스 커밋 실패 정리
- 고유 익명 표식과 학생별 쪽 및 문항 레코드 저장
- 배치 상태, 제출 및 검토 수 조회
- 익명 표식을 숨긴 지역 학생 배정 목록
- 같은 학급의 미배정 응시 학생만 허용하는 수동 재배정
- 고정 배치 실패 문구와 작업 큐의 고정 실패 문구

## 검사

- 스캔 배치 API 시험: 13개 성공
- 정상 저장, 검토, 분할 실패, 부분 결과, 커밋 실패와 예약 실패 정리 시험 성공
- 업로드, 쪽 수, 준비 상태, 집계, 재배정 소속과 중복 시험 성공
- 전체 백엔드 시험: 589개 성공
- `compileall`, `git diff --check`: 성공
- 기존 사용 중단 예정 경고 7개, 새 경고 없음

## 남은 위험

- 전원이 꺼지는 정확한 순간에는 최종 폴더 이동과 데이터베이스 커밋 사이에 고아 폴더가 생길 수 있어 시작 시 정리 절차가 있으면 더 좋다.
- 현재 파이프라인은 PDF 전체 페이지를 메모리에 올리므로 큰 학급과 긴 답안지는 5천 쪽 및 전체 화소 제한 안에서도 메모리 측정이 필요하다.
