# P5 구현 보고서

## 결과

- 교사가 정한 세 경계값에 따른 엄격한 성취수준 판정과 출발값 제안
- 성공한 실행의 완전한 확정 점수와 정확한 루브릭 조항만 쓰는 입력 조립
- 익명 표식과 학년 말투, 엄격한 출력 계약을 강제하는 피드백 생성
- 외부 실패와 불완전한 출력을 확정 루브릭 조항 기반 문장으로 낮추는 안전 경로
- 현재 자료 정책과 현재 키에 연결된 모형을 다시 확인하는 원자적 생성 API
- 점수나 루브릭이 바뀐 오래된 피드백 표시와 인쇄 차단
- 지역에서만 자연스럽게 실명을 넣는 학생별 인쇄 문서
- 문항별 점수와 총점과 수준, 문항 평균과 평균 득점률 성적표
- 경계값 추천과 피드백 상태, 내보내기를 제공하는 반응형 화면

## 설계 반영

- 7.7절에 따라 외부 입력에는 익명 표식과 점수와 루브릭만 넣고 실명은 지역 렌더링에서만 넣는다.
- 9절에 따라 확정 점수와 적용 조항으로 문항 설명을 만들고 총점 경계값으로 수준을 결정하며 학년 말투와 다음 행동을 요구한다.
- 10절에 따라 실행과 학생마다 피드백 하나를 저장하고 생성 원본 지문으로 오래된 자료를 찾는다.
- 11절에 따라 지역 파이썬 템플릿과 성적표 도구를 사용하며 외부 글꼴이나 원격 자료를 넣지 않는다.
- 13절과 14절에 따라 합성 자료 검사를 현장 성능 근거로 쓰지 않고 실제 학급 측정 절차를 남긴다.

## 검사

- 전체 서버 검사 875개 성공
- 프런트엔드 엄격 자료형 검사와 제품 빌드 성공, 51개 모듈
- 프런트엔드 배포 의존성 취약점 0건
- 넓은 화면과 390화소 화면에서 피드백 두 장, 대체 문장, 내보내기와 가로 넘침 없음 확인
- 점수 변경 뒤 오래된 카드와 경고가 나타나고 인쇄 링크가 사라지는 것 확인
- 기존 사용 중단 예정 경고 7개, 새 경고 없음

## 남은 위험

- 실제 한 학급의 외부 생성 문장 품질과 전체 처리 시간, 종이 채점 비교는 실제 자료와 교사 시간이 필요하다.
- 실제 피디에프 저장과 인쇄기의 한글 출력은 현장 컴퓨터에서 확인해야 한다.
- 실제 답안 파일럿이 끝나기 전에는 자동 확정 범위를 넓히지 않아야 한다.
