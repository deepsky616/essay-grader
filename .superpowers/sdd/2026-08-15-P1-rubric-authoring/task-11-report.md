# 작업 11 보고

## 상태

완료. 시작 기준은 `b89b3ca`이고 구현 커밋은 `cd491fa`다.

## 실패 뒤 성공 근거

- 먼저 평가 관리 API 시험 스물네 건을 작성했다.
- 첫 초점 검사에서 모든 요청이 아직 등록되지 않은 경로의 404 응답을 받아
  예상대로 실패했다.
- 입력과 출력 스키마, 평가 라우터, 오류 경계, 앱 라우터 등록을 구현했다.
- 최종 초점 검사 스물네 건과 전체 백엔드 검사 이백삼십삼 건이 통과했다.

## 구현 내용

- 평가 만들기, 최신순 목록, 단건 조회, 부분 수정, 삭제 경로를 추가했다.
- 평가명, 과목, 학년, 총점, 성취기준, 수준 경계값을 만들기와 수정 입력에서
  모두 받고 응답에서도 같은 값으로 돌려준다.
- 평가명과 과목의 빈 문자열 및 공백 문자열, 범위 밖 학년, 영 이하 총점,
  알 수 없는 입력 칸, 빈 수정 요청, 명시적인 null 변경을 422로 거부한다.
- 기존 공용 수준 경계값 규칙을 재사용해 총점 범위 밖 경계값과 낮은 총점으로
  기존 경계값을 무효화하는 수정을 422로 거부한다.
- 없는 평가는 읽기, 수정, 삭제 모두 고정된 404 응답으로 처리한다.
- 쓰기 중 고유값 또는 외래 키를 포함한 자료 무결성 오류가 나면 세션을
  되돌리고 원래 질의문이나 드라이버 내용을 내보내지 않는 고정 409 응답으로
  바꾼다.
- 평가 삭제는 실제 파일이 없는 `SourceDocument`와 `RubricDraft` 연관 행의
  데이터베이스 연쇄 삭제를 확인했다.
- 설정 라우터를 유지하면서 현재 실제로 존재하는 평가 라우터만 앱에 누적
  등록했다. 문서 업로드와 루브릭 API는 추가하지 않았다.

## 로컬 파일 삭제 판정

작업 12 계획은 업로드 파일을 만든 뒤 문서 행을 저장하지만 평가 삭제와 파일
정리를 묶는 저장 서비스 계약을 아직 제공하지 않는다. 지금 평가 삭제에서 파일을
직접 지우면 작업 12의 저장 경계를 앞질러 구현하고, 임의의 `stored_path`를 믿어
사용자 파일을 지울 위험이 있다.

따라서 연결 문서의 로컬 경로에 파일이나 심볼릭 링크가 실제로 있거나 경로 상태를
안전하게 확인할 수 없으면 평가 삭제를 409로 막는다. 파일이 이미 없을 때만 평가와
연관 데이터베이스 행을 연쇄 삭제한다. 이 판정으로 정상 순서에서는 새 고아 파일을
만들지 않지만, 경로 확인 직후 다른 과정이 같은 위치에 파일을 만드는 매우 짧은
경쟁 구간은 남는다. 작업 12 이후 전용 저장 서비스가 파일 정리와 데이터베이스
삭제를 하나의 보상 가능한 흐름으로 묶어야 완전히 닫힌다.
