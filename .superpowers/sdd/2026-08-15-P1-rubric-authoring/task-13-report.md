# 작업 13 보고서

상태: 완료. 작업 수 한도로 주 에이전트가 구현과 읽기 전용 검토를 함께 수행했다.

## 구현

- 루브릭 컴파일, 조회, 수정, 확정, 확정 해제 API
- 컴파일 원문 종류 제한과 번호 기준의 안정된 순서
- 지역 업로드 폴더 바로 아래 일반 PDF만 허용하는 닫힌 경로 검사
- 현재 API 키와 해당 키에 묶인 모형의 잠금 구간 일괄 읽기
- 단일 전송 관문을 소유한 제공자 실행 손잡이 생성
- 제공자 오류, 자격 정보 오류, 지역 경로, 잘못된 입력값을 되비추지 않는 고정 오류
- 평가별 루브릭 초안 하나의 새 저장과 다시 컴파일 갱신
- 선생님 평가 정본을 조회, 수정, 확정 때마다 최신 값으로 덮어 적용
- 형태 오류와 업무 규칙 오류의 분리, 비차단 경고 재계산
- 확정 뒤 루브릭 수정, 재컴파일, 평가 정본 수정을 막는 잠금과 명시적 해제
- 저장 실패 때 세션 되돌림과 고정 오류

## 판정

Ruling: API 키와 모형을 따로 읽지 않고 같은 설정 잠금 구간에서 현재 키와 그 키에 묶인 모형을 함께 읽는다 — 키가 바뀌는 순간 예전 모형 선택을 다른 키로 실행하지 않기 위해서다 — 이 판단이 틀리면 설정 읽기 함수가 하나 더 늘어난다.

Ruling: 데이터베이스의 원문 경로를 그대로 믿지 않고 앱 업로드 폴더 바로 아래의 무작위 이름 일반 파일만 컴파일 입력으로 허용한다 — 지역 경로가 손상되거나 바뀌어도 앱 범위 밖 파일을 외부로 보내면 안 되기 때문이다 — 이 판단이 틀리면 옛 방식으로 저장한 임의 이름 원문을 다시 올려야 한다.

Ruling: 평가 정본은 조회, 수정, 확정 때마다 최신 평가 행에서 덮어 적용한다 — 컴파일 뒤 선생님이 제목이나 총점을 바꾸더라도 확정 루브릭이 예전 정본과 어긋나면 안 되기 때문이다 — 이 판단이 틀리면 조회 응답의 정본 칸이 저장된 초안과 달라질 수 있다.

Ruling: 확정 상태에서는 루브릭 수정과 재컴파일뿐 아니라 평가 정본 수정도 막고, 명시적 확정 해제 뒤에만 허용한다 — 확정된 채점 기준의 추적 가능성을 지키기 위해서다 — 이 판단이 틀리면 작은 제목 수정에도 확정 해제가 한 번 더 필요하다.
