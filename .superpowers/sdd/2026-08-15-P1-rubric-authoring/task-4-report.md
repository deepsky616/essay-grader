# 작업 보고

## 상태

완료. 루브릭 구조 검증기와 그 단위 검사를 추가했다.

## 실패 뒤 성공 근거

- 실패: 검사를 먼저 추가한 뒤 실행했을 때 `app.services` 모듈이 없어 수집 단계에서 실패했다.
- 중간 실패: 배점 초과 오류의 문구가 검사 단언과 달라 한 건이 실패했다.
- 성공: 오류 문구를 조정한 뒤 초점 검사 열한 건과 전체 검사 열여덟 건이 모두 통과했다.

## 실행한 검사와 결과

- `cd backend && pytest tests/test_rubric_validator.py -v` 처음 실행: 모듈 부재로 실패.
- `cd backend && pytest tests/test_rubric_validator.py -v` 최종 실행: 열한 건 통과.
- `cd backend && pytest -q`: 열여덟 건 통과.
- `git diff --check`: 문제 없음.

검사 실행 중 기존 비동기 검사 도구에서 폐기 예정 경고가 나왔으나 실패는 없었다.

## 바뀐 파일

- `backend/app/services/__init__.py`
- `backend/app/services/rubric_validator.py`
- `backend/tests/test_rubric_validator.py`

## 자체 검토

- 배점 합계, 문항 번호 연속성, 만점과 영점 기준, 배점 초과를 검사한다.
- 자동 채점 유형별 정답 후보, 복합 문항 하위 파트와 배점 합계, 성취기준 식별자, 성취수준 컷오프 범위를 검사한다.
- 모든 오류를 목록으로 모아 반환하므로 한 번의 검증에서 여러 문제를 확인할 수 있다.
- 스키마의 조건식 문법 검사를 변경하지 않아 자료형 책임과 업무 규칙 책임을 분리했다.

## 걱정거리

조건식의 문법 자체는 기존 스키마가 담당한다. 문항 유형별 조건식 조합의 세부 의미 규칙은 현재 작업 명세에 포함되지 않아 추가하지 않았다.

## 수정 보고

### 수정 내용

- 문항 유형별 채점 조건 조합을 검증한다. 작도는 `manual`만, 자유 서술은 `llm`만 허용한다.
- 단답, 수치, 택일, 복합 문항은 결정론 조건만 허용하며, 표 문항은 집합 조건만 허용한다.
- 택일 문항의 정답 선택지가 선택지 후보 안에 있는지 검사한다.
- 표 문항의 모든 열에 정답 후보가 있는지 검사하고, 복합 문항 하위 파트에도 같은 후보 검사를 적용한다.
- 성취기준이 존재하더라도 연결된 문항 번호가 해당 문항 범위 밖이면 오류를 반환한다.

### 실패 뒤 성공 근거

- 실패: 새 회귀 검사 추가 직후 초점 검사에서 다섯 건이 실패했다. 조건 조합, 택일 후보, 표 열 후보, 복합 하위 파트 후보, 성취기준 범위 검사가 없었기 때문이다.
- 성공: 검증기를 보강한 뒤 초점 검사 열일곱 건과 전체 검사 스물네 건이 모두 통과했다.

### 실행한 검사와 결과

- `cd backend && pytest tests/test_rubric_validator.py -v`: 열일곱 건 통과.
- `cd backend && pytest -q`: 스물네 건 통과.
- `git diff --check`: 문제 없음.

기존 비동기 검사 도구의 폐기 예정 경고는 계속 나오지만, 검사 실패는 없었다.

### 바뀐 파일

- `backend/app/services/rubric_validator.py`
- `backend/tests/test_rubric_validator.py`
- `.superpowers/sdd/2026-08-15-P1-rubric-authoring/task-4-report.md`

### 자체 검토

- 조건 조합 오류와 정답 후보 오류를 규칙별로 누적해 한 번에 돌려준다.
- `partial` 조건은 스키마가 보장하는 두 문법을 모두 허용한다.
- 성취기준 범위는 양 끝 값을 포함해 검사한다.

### 걱정거리

성취기준의 문항 범위 시작값과 끝값이 뒤집힌 입력은 현재 스키마와 검증기에서 별도로 막지 않는다. 현재 명세의 정상 범위 자료를 전제로 한다.
