# 작업 15 보고서

상태: 완료. 작업 수 한도로 주 에이전트가 구현과 읽기 전용 검토를 함께 수행했다.

## 구현

- 불러오기, 실패, 빈 상태를 구분하는 평가 목록
- 평가 정보와 세 종류 PDF를 순서대로 처리하는 새 평가 화면
- API 키와 현재 키에 묶인 모형을 평가 생성 전에 확인하는 사전 검사
- 평가 생성 뒤 부분 실패 때 평가 번호와 성공한 문서 종류를 기억하는 이어서 처리
- 실제 자격 정보 저장 계약을 설명하는 설정 화면
- API 키 저장과 삭제, 모형 목록 조회와 선택, 자료 정책 확인
- 키 변경 때 모형 선택과 화면 목록을 다시 고르게 하는 흐름
- 화면 읽기 도구를 위한 알림 영역, 입력 이름, 버튼 종류

## 판정

Ruling: API 키나 모형이 없으면 평가 행을 만들기 전에 중단한다 — 설정 누락 때문에 루브릭이 없는 빈 평가가 쌓이는 일을 줄이기 위해서다 — 이 판단이 틀리면 설정을 나중에 하고 같은 새 평가 화면에서 곧바로 이어갈 수 없다.

Ruling: 평가를 만든 뒤 문서 업로드가 일부 실패하면 새 평가를 다시 만들지 않고 같은 평가 번호와 이미 성공한 문서 종류를 화면 상태에서 기억한다 — 지역 파일과 데이터베이스 행의 중복을 줄이기 위해서다 — 이 판단이 틀리면 화면을 벗어났다가 돌아왔을 때는 뒤 작업 16의 다시 컴파일 흐름을 써야 한다.

Ruling: 키 저장 안내는 키체인 우선과 설정된 암호화 키 기반 대체 파일만 설명한다 — 백엔드는 평문 권한 파일로 떨어지지 않고 안전하게 거절하기 때문이다 — 이 판단이 틀리면 키체인을 쓸 수 없는 환경에서 별도 설정이 필요하다는 안내가 길어진다.
