# 작업 10 보고

## 상태

완료. 시작 기준은 `6bf1bcb`이고 구현 커밋은 `5749c89`다.

## 실패 뒤 성공 근거

- 먼저 문서와 루브릭 초안 저장 시험을 작성했다.
- 첫 초점 검사에서 `app.models`가 `RubricDraft`를 내보내지 않아 수집 단계에서
  예상대로 실패했다.
- 모델과 관계, 제약, 중첩 JSON 변경 추적, SQLite 외래 키 설정을 구현했다.
- 첫 성공 시도에서 연쇄 삭제 시험이 세션에 남은 오래된 객체를 읽어 한 건 실패했다.
  세션을 비운 뒤 데이터베이스에서 다시 읽도록 시험 관찰 지점을 바로잡았다.
- 최종 초점 검사 열네 건과 전체 백엔드 검사 이백아홉 건이 통과했다.

## 구현 내용

- `SourceDocument`가 평가 식별값, 문서 종류, 원래 파일 이름, 로컬 저장 경로,
  쪽 수와 생성 및 갱신 시각을 보관한다.
- `RubricDraft`가 평가별 하나의 루브릭 내용, 경고 목록, 확정 여부와 생성 및 갱신
  시각을 보관한다.
- 평가에서 문서 목록과 루브릭 초안으로 가는 양방향 관계를 추가했다.
- 평가 삭제 시 두 새 표의 연관 행이 함께 지워지도록 관계 삭제 규칙과 데이터베이스
  외래 키 연쇄 삭제를 함께 적용했다.
- SQLite 연결마다 외래 키 검사를 켜서 존재하지 않는 평가를 가리키는 행을 거부한다.
- 루브릭 내용과 경고의 사전과 목록을 모든 깊이에서 감싸, 안쪽 목록 추가나 안쪽
  사전 값 변경도 저장할 수 있게 했다.
- 모델 묶음 내보내기에 현재 존재하는 평가, 문서, 루브릭, 앱 설정, 정책 확인 사건
  모델을 누적 등록했다. 이 등록으로 새 데이터베이스와 기존 데이터베이스 모두
  `init_db`에서 새 표를 반복 안전하게 만든다.
- 외부 호출이나 뒤 작업의 API는 추가하지 않았다. 원문 경로는 로컬 자료만 가리킨다.

## 검사 결과

- 구현 전 `pytest tests/test_models_document_rubric.py tests/test_db_migrations.py -q`:
  새 모델 내보내기 부재로 예상 실패.
- `backend/.venv/bin/pytest tests/test_models_document_rubric.py tests/test_db_migrations.py -q`:
  열네 건 통과, 기존 외부 도구 경고 두 건.
- `backend/.venv/bin/pytest tests/ -q`: 이백아홉 건 통과, 기존 외부 도구 경고
  일곱 건.
- `backend/.venv/bin/python -m compileall -q app tests`: 통과.
- `git diff --check`: 통과.
- `git diff --cached --check`: 통과.

기본 파이썬 환경에는 피디에프 패키지가 없어 전체 검사가 수집 단계에서 한 번
멈췄다. 저장소의 개발 가상 환경에는 잠금 의존성이 모두 설치되어 있어 같은 전체
검사가 정상 통과했다.

## 남은 위험

- 평가 삭제는 연관 데이터베이스 행을 지운다. 실제 업로드 파일은 모델 사건 처리로
  지우지 않았다. 이후 평가 삭제 기능을 만들 때 저장 성공과 파일 정리를 묶는 전용
  서비스에서 로컬 파일을 안전하게 지워야 한다.
- 외부 의존성에서 사용 중단 예정 경고 일곱 건이 남아 있다. 이번 변경에서 새로 만든
  경고는 아니며 검사 결과에는 영향을 주지 않는다.
