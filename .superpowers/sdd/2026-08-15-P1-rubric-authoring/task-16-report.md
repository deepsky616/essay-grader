# 작업 16 보고서

상태: 완료. 작업 수 한도로 주 에이전트가 구현과 읽기 전용 검토를 함께 수행했다. 실제 브라우저 검사는 `browser-qa`와 `chrome:control-chrome` 지침을 적용했다.

## 구현

- 문항 정보, 정답 후보, 점수 조건, 기준 원문, 예시 답안의 구조화 편집
- 쉼표가 들어간 수치도 그대로 보존하는 목록 항목별 편집과 추가, 삭제
- 복합 문항과 빠진 구조를 위한 전체 JSON 저장과 서버 검사
- 평가 정본 API를 통한 3, 2, 1수준 경계값 편집
- 저장, 업무 오류 표시, 확정 잠금, 명시적 확정 해제
- 초안이 없는 평가의 저장 문서 다시 컴파일과 기존 초안 재컴파일 확인
- 형태가 깨진 JSON은 기존 정상 초안을 바꾸지 않는 고정 422
- 직접 화면 주소 새로고침, 실제 자산, 알 수 없는 API를 구분하는 정적 서빙
- 375 폭에서 접히는 문항 배치와 표 내부 가로 이동

## 판정

Ruling: 스키마 형태가 깨진 루브릭은 저장하지 않고, 스키마는 맞지만 업무 규칙이 어긋난 루브릭만 검토 초안으로 저장한다 — 프런트와 뒤 채점기는 루브릭 형태를 신뢰하므로 깨진 JSON을 영구 저장하면 화면과 채점이 멈출 수 있기 때문이다 — 이 판단이 틀리면 옛 깨진 초안은 직접 데이터 이행이 필요하다.

Ruling: 수준 경계값은 루브릭 저장 요청으로 바꾸지 않고 평가 정본 API에 먼저 저장한다 — 언어 모형과 루브릭 편집이 선생님 정본을 덮어쓸 수 없다는 경계를 유지하기 위해서다 — 이 판단이 틀리면 저장 요청이 두 번 필요하고 첫 요청만 성공한 상태를 화면이 다시 읽어야 한다.

Ruling: 등록되지 않은 화면 GET만 뿌리 문서로 되돌리고 알 수 없는 API와 빠진 자산은 404를 유지한다 — 모든 404를 HTML 200으로 바꾸면 API 실패가 숨겨지기 때문이다 — 이 판단이 틀리면 마침표가 들어간 화면 주소는 직접 새로고침할 수 없다.
